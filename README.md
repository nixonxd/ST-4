# ST-4: модульное тестирование автомата обработки багов

Репозиторий содержит два проекта на .NET 9:

- `BugPro` - консольное приложение с классом `Bug`, моделирующим жизненный цикл дефекта.
- `BugTests` - набор MSTest-проверок для автомата состояний.

В реализации использована библиотека `Stateless`, потому что она удобно описывает переходы между состояниями и позволяет явно тестировать недопустимые триггеры.

## Что реализовано

Вместо примитивного сценария добавлен более жизненный процесс обработки бага:

- регистрация дефекта;
- взятие в работу;
- ожидание ответа от автора;
- перенос в backlog;
- отправка на QA;
- повторное открытие;
- архивирование;
- отдельные ветки `Duplicate`, `Declined` и `NeedMoreEvidence`.

У объекта `Bug` есть не только состояние, но и простые метаданные: краткое описание, ответственный и журнал переходов. За счёт этого тесты проверяют не только смену состояний, но и побочные эффекты модели.

## Структура проверки

В тестовом проекте собраны проверки трёх типов:

- корректные переходы между состояниями;
- недопустимые действия и исключения `InvalidOperationException`;
- служебное поведение: история переходов, строковое описание, доступные действия и инициализация данных.

Количество тестов больше минимального требования, поэтому покрыт как обычный сценарий, так и пограничные ветки автомата.

## Запуск

```bash
dotnet restore
dotnet build
dotnet test
```

## Примечание

Если проверка идёт через GitHub Actions, workflow из `.github/workflows/dotnet.yml` должен успешно проходить шаги `restore`, `build` и `test`.
